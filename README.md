# 136スタジオ予約サイト 修正候補

現在のGitHub mainにはHTML2個しかなく、予約APIと会員APIが欠落しています。この候補はサーバー保存・ログイン・準備片付け時間の競合判定を復旧します。

## 反映前の必須確認

1. 対象は `mufufxmufu/vercel-site` と Vercel `136_studio_vercel_neon_connected`。
2. 既存のNeon `users` / `bookings` テーブルの列・型・既存予約を確認。`schema.sql` は新規DB用の参照定義です。既存テーブルの型が異なる場合、コードを合わせてから反映してください。既存データを消さないでください。
3. Vercelの `DATABASE_URL` を維持し、ランダムな32バイト以上の `AUTH_SECRET` を production に追加。ソースへの秘密値の埋め込みは禁止。
4. VercelはNode.js 24.x、Output Directoryは `public`。保護設定は変更しません。
5. 予約・会員APIと `lib`、`public`、設定を1コミットで反映し、デプロイ完了後に実DBで会員登録・ログイン・予約・履歴を検証。
6. 同じ部屋の同じ日時を2つの独立したセッションから同時送信し、201が1件、409が1件になることを確認。準備片付け時間に重なる予約も409になり、別の部屋では予約できることを確認。

## 利用ルール

営業時間9:00〜21:30内に前後15分を収めるため、予約時間は9:15〜10:15から20:15〜21:15までの60分枠です。前後15分を含む90分を確保するため隣接する60分枠は同じ部屋で選べません。既存予約の時刻はそのまま競合判定に使います。

予約をDBに保存した後にPayPay案内を表示します。支払い完了ボタンだけで決済確認済みにはしません。決済は運営者による確認が必要です。元ソースにあった約款、ロゴ、2部屋別PayPay QRと、提供済みの部屋写真を保持しています。
